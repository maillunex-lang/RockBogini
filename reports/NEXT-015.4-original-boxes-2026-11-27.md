# NEXT-015.4: сундуки только по оригинальным исходникам

Первоисточник: `/home/gamedev/QueensBladeH5/racon2-main/server/lib/racon/game/handlers/item.ex`, `server/lib/racon/game/item/random.ex`, CDN `client/config/configure/*/{ItemConsume,CardSummonType,CardRandomLib}`. Исходные бинарные таблицы декодированы скриптом `tools/export-original-item-consume.py` без предположений о наградах.

Извлечено 1898 ItemConsume, 611 CardSummonType, 699 CardRandomLib; из них 158 RandomBox (SubType 2), 363 RandomBoxAutomatically (5), 3 LockedFixedBox (6), 2 LockedRandomBox (7). У оригинального CardSummonType обнаружено 19 отсутствующих в CardRandomLib ссылок, но **ни одна из них не используется сундуками этих типов**. Это зафиксировано машинно в `reports/NEXT-015.4-source-audit.json`.

Сервер `next-server/src/boxRewards.ts` использует оригинальный порядок цепочек, случайный выбор библиотеки, StartChance в миллионных долях, последнюю гарантированную библиотеку, взвешенную выдачу по RandomLib и ShowLib fallback по оригиналу. Для сундуков исходный Elixir-код сознательно не реализует pity. В `inventory.ts` оплачиваются все материалы открытия (включая сам запертый сундук), фиксированные награды берутся из Param, выпадения и платежи проводятся единой PostgreSQL-транзакцией. Неполный список наград не должен списывать материалы. Авторизация обязательна.

Клиент показывает стоимость открытия, тип сундука и реальные выданные предметы. Проверка: TypeScript сервер и Vite сборки PASS; отдельная PostgreSQL16+Redis7, последовательный прогон **149 PASS / 0 FAIL / 0 SKIP**, включая новые серверные тесты сундуков. Дальнейшая запись результата браузера и деплоя после проверки.

Открытое ограничение: itemBase сложных сущностей, внешние сервисы событий, точные вероятностные эталоны массовых открытий, иные ConsumeSubType, полная 1:1-анимация сундука не считаются завершёнными. Следующим этапом аудит и внедрение оригинальных достижений NEXT-020.2.
